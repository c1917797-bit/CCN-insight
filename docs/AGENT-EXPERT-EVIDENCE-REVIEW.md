# Agent 动态与结论的专家可用性复核

复核日期：2026-10-23。范围为 19 项既有论文／官方资料、本周 4 项精选记录、三项研究建议及七个执行控制点。保留原五段阅读主线、三项研究方向、资料 ID、技术路线与锚点。本次没有新增已完成的云核实验，也没有扩大新闻覆盖声明。

## 原有问题与处理

1. 关键机制和结果原本藏在每条动态的折叠区。现在直接呈现“一句话总结—关键机制—原文结果与条件—架构影响—研究问题”，原文链接、日期和版本在首屏可见。背景、路线关联、演示类比和核验记录留在次层。
2. 标题只描述事件，不能快速定位研究价值。19 条标题统一点出挑战、机制与研究方向；ACTS 明确为排程上游，AgentReplay 明确为评测基础，UCM 明确为缓存正确性前提，避免强行当作新调度算法。
3. “建议验证”多为动作清单。现已改成有对照、有控制变量、有失效边界的问题，例如缓存节省何时小于排队增量，公平成本预测有误时哪些任务退化。
4. 三项结论改为明确的研究取舍：程序级排程、亲和与饱和退出、成本公平；每项列出穿刺资料、最小对照及继续／停止条件。跨层联合优化置于单项净收益之后。
5. 专家不需要每条都读咖啡类比。类比保留在详情中，主要阅读层使用任务、模型副本、工作集、预算和系统成本等术语。

- **Dyserve**：复核原文表 1、§7.3。保留 18.1%→67.2% 的突发窗口 goodput，以及全轨迹 75.8%→69.2% 的准确率变化；明确二者统计窗口不同，不能写成质量无损加速。
- **ThunderAgent**：复核附录 A.5。8×A100、并发 24 与 48／72 的条件及工作集压力差异保留，不能把高并发收益用于所有并发或昇腾。
- **Justitia**：复核 §5.2 与图 7／8。补入相对 VTC 仍有 8% 任务完成更晚、最坏延迟增幅 26.0%；避免只报告平均 JCT 改善而隐藏任务退化。
- **AgentReplay**：查看原文记录／回放定义。保留 token、依赖与工具时长回放用途；它控制性能比较的工作量，不证明自由生成的任务质量或真实工具争用。
- **生产 Agent 负载研究**：重读原始摘要。1170 万请求与万卡平台仍限定为该平台样本；逻辑兄弟请求少重叠用于校准实验负载，不作为某算法收益证据。
- **LearnSched**：查看原文有限模型和状态成本结构；保留既有局部核验结果，不把净价值模型结果换算为生产任务吞吐。仅在在线与后台任务争用时进入候选研究。
- **动态子 Agent 并发研究**：查看原始摘要与研究范围。并发协作是工作负载变量，系统排程是另一变量；保持编码 Agent 范围，分别记录预算、汇合和并发写入失败。

## 研究决策与事实的界线

- 本期动态回答发生什么、机制是什么、原文在什么条件下观察到什么。
- 架构影响回答该证据要求新增什么状态、接口或回退能力，为本报告判断。
- 分析结论回答优先穿刺哪项机制、用什么基线、哪些观测会使建议失效。
- 调度有效吞吐以任务达标为单位，不能由 token 吞吐、命中率或并发量直接替代。所有失败、拒绝和超时继续计入任务账本。
