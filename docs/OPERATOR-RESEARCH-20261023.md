# 算子定制加速研究维护说明

本轮仅更新本地 CCN 预览，不推送 GitHub，不发布 CCN 或原站。

## 内容结构

- 一级分类仍为“算子定制加速”，二级标题严格保留“计算算子加速”“通信算子加速”。
- 计算侧按数据搬运与片上复用、分块映射与并行流水、融合与启动优化、布局与低精度执行组织。
- 通信侧按集合算法与拓扑映射、启动与消息粒度、数据路径与缓冲管理、通算融合与异步重叠、传输编码与通信量压缩组织。
- 自动生成与自动调优是实现、搜索和验证上述机制的方法，不另设同级根技术。310P 自动生成与优化仅作为计算侧提升开发与调优效率的工程实践，不放进顶部同级导航。
- 九项子技术分别使用统一专题结构：研究背景、基本原理、关键挑战、技术进展、比较判断、工程实践、研究结论；技术进展先产业实现、再学术依据，保留证据覆盖不足的说明。
- 模型内部表示改变归推理压缩；仅传输时的编码压缩归通信算子；改变 TP/PP/EP 等并行划分归组合调度。

## 310P 既有材料的证据边界

既有材料为 `Ascend310P_12_Page_Report_v2.pptx`，SHA-256 为 `88f0f244a6454d541994ea455653c3ec5d02a26e7839efd5abc5663bfecf1400`。

本次读取既有报告，未执行其中的工具、CANN、仿真或设备测试。“已有实现”仅指原报告对其代码快照或 Agent 规约的认定。将生成、编译、正确性、单算子性能和整模收益分开，不将工程模板生成写成完整内核生成，不把其他芯片结果外推为 310P 支持。

页面保留原报告页码和相对代码定位。报告二进制与本机绝对路径不进入网站产物。后续补入设备证据时，应记录实际 SoC、软件栈、候选源码和产物指纹、输入、独立参考、基线、数值容差、热身计时方法与耗时分布。失败任务保留在通过率分母中，搜索预算单列。
