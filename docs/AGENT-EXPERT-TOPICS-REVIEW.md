# Agent 调度专题：专家阅读复核

复核日期：2026-10-23。范围为 3 个根技术、7 个执行对象、5 个兼容入口及共同验收边界；目录文案覆盖整个模块。这里记录正文与证据边界调整，浏览器验收及发布由主任务统一记录。

## 采用的阅读标准

每页必须能回答：决策变量是什么、在线能看到什么、动作何时合法、机制如何起作用、与什么基线比较、何时会失效。研究建议、文献原始事实和本地实验结果分开；当前没有本地性能实验，不新增提升比例或硬件支持承诺。

## 逐页调整

| 页面 | 原问题 | 调整 |
| --- | --- | --- |
| 依赖感知排程 | 启动次序、程序进度和路径预测容易混成一个方案；建议像资产清单 | 用“程序级排队能否减少”形成可否证问题；说明先观测模型排队贡献，再对照 FCFS／MLFQ；排序、选址与预算分开归因 |
| 状态感知映射 | 缓存命中可能被误读为已经产生业务收益 | 对照轮询、最少在途、纯亲和和饱和退出；把状态年龄、查询、排队与传输计入净收益；模型质量和部署位置另设实验 |
| 干扰感知分配 | 服务成本公平与硬件共卡干扰容易同时改动，无法识别因果 | 先验证服务计量，再在固定卡时下测独占／共卡；明确总体吞吐提高但租户护栏失败不采纳；弹性控制仍是储备研究 |
| Agent 接入调度 | 仅列算法名称，缺少接纳、拒绝与会话恢复的接口 | 明确任务类型、权限、状态位置、实例健康和在途量输入；输出接纳结果、实例和排队事件；增加会话热点与实例失效反例 |
| 工作流任务调度 | 子任务为何就绪、排序和选址的边界不够具体 | 明确依赖与授权筛选；对照固定选址 FIFO、程序进度和关键路径；强调未来分支不可泄漏，工具慢返回可能才是瓶颈 |
| 模型路由调度 | 语义选模型与同模型选副本不够清楚 | 先质量受控选模型，再同模型副本选择；分别解释未缓存输入工作量、活跃输出与饱和退出；状态过期列为必要压力场景 |
| 推理批次调度 | 连续批处理、排序与预算容易被当作同一种算法 | 区分逐轮更新运行集合、请求排序与 token／KV 预算；冻结目标引擎版本；长 prefill、decode 和重算成本同时评价 |
| 工具调用调度 | 限流、顺序和外部操作恢复混在路线名称中 | 说明并发计数与令牌桶不同；只读查询与副作用操作分开；结果未知先核验、再受限重试，不宣称检查点等于恰好一次 |
| 资源放置调度 | “容量足够”与可放置性、服务可用性未充分衔接 | 固定硬约束后比较装箱／分散；多卡拓扑、碎片、加载和服务就绪成本单列；普通请求不触发重新部署 |
| 运行重调度 | 超时、失败与结果未知容易引出统一重试 | 先故障分类，再选择等待、原地调整、恢复或迁移；检查点、兼容性和剩余预算作为前置条件；补重复回执与取消竞争反例 |
| 调度输入与验收边界 | 原有事实边界正确，但目录偏长 | 保留数字点单回执与实物送达的不同终点；压缩目录为输入、职责、完成、研究四层 |
| 5 个兼容入口 | 同源正文可能保留旧描述 | 与对应统一对象专题共用渲染，因此同步获得输入输出、实验对照和证据边界；保留原入口 |

三根技术各加一张 SVG 机制链：观测 → 合法性筛选 → 决策 → 执行反馈。它描述研究接口，不绘制虚构性能数据。11 条候选路线增加逐项基线，避免所有路线只写“与简单算法比较”。

## 官方机制核对

- [Ray Serve 架构](https://docs.ray.io/en/latest/serve/architecture.html)及其[官方源码文档](https://github.com/ray-project/ray/blob/master/doc/source/serve/architecture.md)：请求路由与副本执行是不同职责。主文档访问一度返回 429，使用官方仓库同页补充核对。
- [Ray Serve LLM 请求路由](https://docs.ray.io/en/latest/serve/llm/architecture/routing-policies.html)：入口按模型标识选部署，与同部署内的副本选择分开。本文语义质量门控是研究约束，未声称 Ray 自动实现语义质量判断。
- [LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)：节点读取状态、返回更新，边决定后继；检查点位于 super-step 边界，恢复可能重新执行节点，副作用需幂等设计。
- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：检查点与跨线程 store 的职责不同；图状态恢复不等于外部交易恰好一次。
- [vLLM 引擎配置](https://docs.vllm.ai/en/latest/configuration/engine_args/)：单轮 token 预算与调度策略分别配置。没有将在线文档的默认值或能力直接承诺到用户的 vLLM Ascend 版本。
- [Kubernetes Scheduling Framework](https://kubernetes.io/docs/concepts/scheduling-eviction/scheduling-framework/)：Filter 排除不可行节点，Score 对通过筛选的节点评分；这不构成业务工作负载的全局最优保证。

没有重新全文复现 HEFT、DRF、Decima、VTC、AlpaServe 或 Agentix 的实验。已有摘要级、全文级和跨场景方法参照标记保留，未扩大原论文的理论保证。
