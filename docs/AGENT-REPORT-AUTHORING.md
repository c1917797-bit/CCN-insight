## 3. 以读者的问题组织正文

### 技术地图：积累可复用的方法

研究方向保持三项：依赖感知排程、状态感知映射、干扰感知分配。执行对象和决策控制点作为另一层索引，不能把方向、对象与算法拼成同级分类。它们是团队研究组织方式，不能宣称为行业唯一标准。

每个独立专题按以下递进关系组织：

1. **问题与价值**：什么对象在什么约束下，因为什么矛盾出现等待、浪费或不达标；改善什么任务级指标。
2. **机制与路线**：调度器观察哪些状态，比较哪些候选，采取什么动作；动作如何改变队列、放置、缓存或预算。
3. **现有实现**：先写产业实现及接口边界，再写学术路线及其差异；按相同挑战比较，避免与专题无关的泛化新闻。
4. **证据与限制**：原始图表、对照条件、负面结果、未披露项和适用范围。
5. **研究判断**：可以复用什么，缺什么证据，什么条件下值得本地穿刺，什么观察会推翻建议。

短导语可说明范围和阅读收益；正文保留用户要求的事实到结论顺序。一级标题同层回答同一类问题，子结论由该节事实支撑，避免每页堆放同一组空泛卡片。

### 本期动态：解释新变化

每条精选动态应能精炼回答：**什么挑战 → 什么新机制 → 在何种条件下观察到什么 → 对哪条研究路线有什么具体影响**。句式可以自然变化，不强制把四个短语塞入标题。

- 首层保留论文或事件名称、原文链接、发生日期、版本、关联专题和一句话总结。
- 机制与结果直接可读，补充材料分层展开；禁止只写“值得关注、持续跟踪、具有启示”。
- 具体影响点名状态、动作、接口或限制，例如“新增工具等待状态，允许在安全边界暂停会话”，并说明相较现有实现改变了什么。
- 普通新闻保持短；只有影响路线取舍的重要材料进入独立深读，不能将每条信源更新扩成长报告。

### 分析结论：跨材料做取舍

先呈现本期洞察报告，再给路线取舍与重点研究。每个判断关联技术地图，说明不同证据为何支持该取舍及相反证据是什么。重点研究落到具体论文机制、最小对照和继续／停止条件；不重复动态全文。

信息来源仍是持续更新的入口，保持热点资讯、产业界、学术界三张表及表内分类。具体论文放入动态和专题证据。归档保存固定版本、范围和变化，不把历史资料冒充本期新增。

## 4. 一项重点材料至少讲清五件事

| 读者要理解的内容 | 合格证据或表达 |
| --- | --- |
| 矛盾为什么存在 | 一个明确约束或失败场景，能定位到原文；类比与教学假设单独标明 |
| 技术具体如何工作 | 输入状态、候选、约束、选择动作与结果状态；必要时给公式或伪代码，而非只有名称 |
| 为什么能产生收益 | 一个可跟踪的机制例子：如队列次序变化、迁移链、缓存释放、预算重分配 |
| 证据支持到哪里 | 原图或原表、阅读指引、原文定位、比较条件与缺失信息 |
| 我们应如何行动 | 采纳前提、替代路线、最小验证和失效边界；明确为本报告判断 |

**不满足五项时保留实际核验级别。** 摘要级资料可以进入动态，但不能标为全文深读；参考报告已核实的内容，也必须回到原文复核后才能升级本仓库的核验记录。

## 5. 图、数字与结论的证据要求

### 图负责解释或核查

- 全景动画说明任务、Agent 内部 DAG、模型、工具与卡资源的关系；每个专业专题再用自己的机制图说明决策，不能全部复用四个框。
- 机制重绘明确标“解释性重绘”；原始图表明确标“原图／原表”，保留论文版本、Figure/Table 编号与页码，或视频议题及时间码。
- 每张关键图旁说明读图顺序、变量／坐标、比较对象及它支撑哪句话。原图可放大，放大后内容仍须可辨认。
- 动画中的粒子和箭头对应实际请求或控制事件；依赖边、调用边、部署关系和反馈关系有清晰区别。教学模拟不伪称真实测量。

### 数字保留比较口径

每个关键结果记录：来源版本及定位、指标与单位、基线、模型／硬件、负载／输入输出规模、并发或批量、精度、统计窗口、权衡及未披露项。允许字段缺失，但必须写清缺失；不填推测值。

理论上界、厂商报告、独立实验、本地实测分开；平均数、中位数、尾延迟分开；百分点与相对百分比分开。条件不同不拼成一个收益范围。派生计算标公式、输入数与舍入方式。摘要和表格、投屏和口述不一致时并列说明，不替作者消除矛盾。

### 结论回到团队研究

建议说明：优先研究的具体机制 → 相对当前基线的可证伪假设 → 测什么任务级结果及代价 → 哪种结果使建议失效。GPU 论文收益不得直接承诺为昇腾收益；适配、发布、运行正确与端到端提速分别验收。

## 6. 表现形式与性能的取舍

继承长报告的章节递进、重点突显、图文邻近和证据入口。网页正文自适应，常用目录和结论可快速定位；不能把固定 1920×1080 的单页证据板整体缩成网页正文，重现小字和横向溢出。

所查成品采用内嵌素材的 SingleFile 形态，适合保存固定版本；本次没有逐项完成离线依赖验收。所查 Dynamo 成品约 15.7 MB，包含大量原始投屏与转写；不能将这种素材包全内嵌进本报告首页。在线主阅读层保留精炼机制与必要图，完整素材按需载入，固定版本另行归档。每次做性能承诺都记录真实加载测量，不能由文件变小推定首屏已低于 2 秒。

继续使用分表 CSV 维护来源、事实、路线关联和研究建议；页面是这些材料的阅读视图。原文、采集包、分析、实验结果与最终交付分别管理，不复制私密凭据，也不搬运第三方整套内容。

## 7. 当前差距与补强次序

v31 已具备五段主线、三张信源表、专题接口、对照和停止条件。差距集中在部分论文只有摘要级核对、原始图表不足、机制例子不够具体，不能靠新增卡片掩盖。

1. **优先补原文理解**：选直接影响三项研究方向的材料，逐项复核正文、原图和结果条件。Murakkab 是与参考成品差距明确的案例；目前仍保留摘要级核验。
2. **再补专题机制**：用队列、工作集或放置的真实变化替代通用接口图，加入可追踪的微例子，连接现有实验合同。
3. **再做视觉验收**：独立检查者实际打开每节截图；同时检查桌面、手机、放大图和导航，记录问题及复查结果。程序检查通过不等于视觉验收通过。
4. **最后提炼本期观点**：从已核实证据推导跨论文取舍，保存相反证据、研究条件和版本。未经验证的方向仍标建议。

这些是下一轮内容工作的优先次序，不是本次已完成的网页改造清单。本次完成学习总结与规范落库；未新增论文事实、未调整来源核验级别、未重新发布网站。
