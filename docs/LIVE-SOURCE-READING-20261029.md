## 当前实现

- scripts/collect_compression_abstracts.py：官方 arXiv API 分页，保留原始摘要、版本、日期、哈希和原始响应；获取不自动升为已读。相同输出目录只允许同一查询，改变窗口必须另建目录。
- scripts/refresh_registered_sources.py：从唯一源登记表读取启用的 P0/P1 外部入口，获取索引或官方 release 正文；访问失败、证书错误和超限单独记录，不关闭证书验证。
- scripts/build_live_reading_review.py：只合并实际完成的模型注解，通过 paper ID、abstract SHA、唯一性和必填内容检查，生成本地研读台和 CSV。没有注解就是未读，不能由程序模板补成已读。
- scripts/test_abstract_acquisition.py：验证原始摘要保留、错误响应拒绝、模型阅读状态不自动提升，以及版本绑定。

## 本地阅读与重建

运行 `python scripts/build_live_reading_review.py --acquired .tmp/live-abstracts-20261029 --reviewed .tmp/live-review-20261029 --coverage .tmp/registered-source-refresh-20261029 --out <本地输出目录>`。输出的离线研读.html已内嵌数据，无须联网或启动服务器；index.html版本需要普通本机静态服务。搜索可以匹配原始摘要，避免方法名称不在论文标题里时漏检。CSV保留排除理由，经典论文不计作近90天新论文。

section-reviews.json只登记实际核对过的章节、版本及条件。页面将此层与摘要阅读分开；full_text_read保持零，不将核对几个关键章节包装成通读全文。例：UC-RAMP按相同25%路由专家通道剪枝配置记录质量与TTFT/TPOT，而不把50%剪枝质量结果拼接到25%的部署收益上。

入口重新获取保留previous_attempts。只支持公开HTTPS目标及正常GET跳转，308兼容不放宽证书与地址检查。GitHub Trending按索引读取，不冒充Git仓库。仓库发布说明首次分页与会议导航页读取成功，都不表示90天文章或论文完整获取。

新流程的质量回归检查：`python scripts/test_abstract_acquisition.py`。它覆盖原始摘要保留、不自动提升阅读状态、ID/版本绑定、错误XML拒绝、公开HTTPS跳转保护；这些程序检查不证明语义注解正确，重点判断仍须核对原始证据。

`snapshot_live_reading.py`接受同样的四个目录参数，将原始采集包、实际模型注解、指定章节及产业研读记录保存到本地输出的original-records/，并生成文件哈希清单。该备份不用TableGit、不上传；继续研读后应重建页面并刷新备份，二者都是带时间的快照。恢复时以ID＋摘要哈希识别已读项，不能仅凭分片文件名猜完成范围。

产业重点材料独立计数。目前包含ReplaySSM、流式ASR案例、vLLM-Ascend rc1/rc2、NCNN与CUTLASS六份实际阅读记录。公开事件、证据条件、技术判断分开；不将它们算进arXiv论文摘要阅读数。热点索引浏览仍只算发现线索，不冒充已核验事件正文。
